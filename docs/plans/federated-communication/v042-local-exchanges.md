# V0.4.2: remote-task interactions in local Bot exchanges

V0.4.2 includes conversation hide/show, pinning and confirmed local history deletion, the DSH migration fixes, and this message-flow change. Plugin, Hub and desktop package metadata advance together; the wire protocol and capability requirements do not change.

Use the existing local Bot-pair exchange drawer. Messages from an owned Bot working in a remote Session retain that same Bot identity when it talks to a local teammate or unpublished Chief. The local source chip, earlier-part event and consultation/report/reply tools open the same pair. Remote execution Session aliases come only from host-owned bindings and cannot replace an existing Bot identity. The roster carries only consultation IDs/participants/status and remote-origin turn IDs, never consultation prose or reasoning.

The pair ledger already contains delivered remote requests, reports and ordinary message_bot replies. Completed consultations store their durable result separately in state. The exchange reader projects those exact saved results into the pair history with a stable ID and original receipt, including historical results, without fabricating a Session delivery or waking either Bot. Results being saved, failed results and other pairs remain unavailable. Long answer expansion reads the same authorized stored result and preserves the normal display limit.

The drawer labels remote-task messages and consultation results. Hidden remote turns may show only a compact peer/exchange action; their assistant prose, reasoning, arbitrary tool arguments and outputs remain hidden. Ordinary local hidden turns retain existing behavior. UI inspection never publishes to Hub/user feed, creates a request, or changes delivery acknowledgments.

Validation covers every bridge tool and source chip, earlier parts, stable same-pair identities, complete saved answers, repeated result reads, save-in-progress/failure, historical results after restart, no duplicate delivery, native/PTC nested tool cells, unknown targets, private output isolation, and the existing drawer at desktop/mobile sizes.

Verified on Linux with mock models: DSH 0.2.1-rc.4 and 0.2.2-rc.1 each ran 2,299 plugin tests with zero failures (8 and 5 skips respectively). Hub: 223 passed. Desktop: 231 passed / 1 skipped; clean install and build passed. All 52 host smoke steps passed. A genuine dual-host late consultation through an unpublished local responder produced one request and one saved result in the native pair drawer; full answer reads and restart identity were verified. Desktop and 390px dark mobile production React/CSS checks cover both entry buttons, remote provenance labels, Show all expansion and private tool-text exclusion. Lint and generated-client checks passed. Windows runs remain in CI; screenshots stay under ignored `.dsh-test-tools/local-exchanges-ui/`.
