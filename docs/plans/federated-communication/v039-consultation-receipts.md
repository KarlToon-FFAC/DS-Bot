# V0.3.9：本地咨询答复回执与恢复

本批次包含已通过的联系人申请从界面列表移除，以及 2026-11-13 报告的本地咨询答复可靠性修复。版本暂保持 V0.3.8，等待发布指令。

## 已确认的问题与诊断边界

现有自动咨询收尾捕获保存失败后只写日志；缺少咨询记录时直接返回，不能证明送达。咨询结果保存在本机状态文件后，只能由发起方轮询；单次等待最多 30 秒，发起方结束回合后没有主动结果通知。通用收尾规则还可能催促等待中的 Bot 选择“不回复”，提前封闭该远程消息的回复决策。原报告没有提供完整会话事件，因此不能断言现场一定是其中哪条路径，但这些缺口都能由代码及故障注入复现。

另有明确入口问题：consult_local_bot 的通用通信包装先取得 Hub actor，导致未发布的本地答复方收到 BOT_NOT_PUBLISHED，而没有得到正确的答复指引。并发到达的咨询请求在被重新排入独立回合时，也没有保留 remoteSource。

## 行为

- 发起或续等工具与答复工具分开。`consult_local_bot` 的组合参数先校验；首次给 botId/text，可用 requestId 标识一次请求；续等只给 consultationId/waitSeconds。错误轮询不删除任何有效咨询。
- 未发布的本地答复方使用 `reply_to_local_consultation({consultationId,text})`，或在原咨询回合中向请求方 `message_bot`。后者直接保存咨询答复，不再承诺稍后自动送达。收到的本地消息头含准确的咨询 ID 和工具示例。
- 答复只有在 required 保存成功后才返回回执；按咨询序列化，重复同一答复返回同一 receiptId，完成后不同正文被拒绝。回合最终正文不能覆盖已提交答案。保存过程中的查询不得提前读到“已完成”。`completed` / `resultState:durably_saved` 只表示内部结果已持久化，不代表远端已经收到，也不证明任务结论正确。
- 自动收尾仍作为兼容路径，直接存放完整正文，不依赖附件服务，不包含思考。最长 128000 字符，超限给明确错误，不静默截断。
- 保存失败给本地答复方失败通知、保留待恢复正文，并在运行时与请求方结果查询中暴露未确认状态。空答复及超限为失败状态，需要明确重提，不无限重试坏正文。
- 待咨询时允许发起方结束当前模型回合；标记 awaiting_local_consultation，而不是 no_reply，不消耗收尾纠正次数。结果或失败通过绑定原始投递的内部宿主通知回到原远程会话，不改原作者、会话、成员 epoch 或因果来源。通知自身不发布 Hub 消息，结果仍由 Bot 显式发送。
- 通知前重查授权、持久会话及队列；已由真实 consult 工具结果收到的回执不重复通知。通知写入后状态保存失败，利用原生会话证据恢复，避免重复唤醒。授权撤销或原绑定丢失时保留结果并显示错误，请求 Bot 仍可在本地按 ID 查询自己已有的咨询。
- 请求投递不确定时不自动重新派单，清理悬挂 work 并保留可查询的 delivery_unknown。超过十分钟没有结果转为明确超时；不会声称成功，也不会强行中断被咨询 Bot。晚到的有效答复仍可保存。
- 重启后从被咨询 Bot 的原生历史恢复“只有该咨询作为输入、正常完成”的正文；混合回合不猜测受众。正常回合跟踪保留并发、延期与重试的原始来源。

## 验证

- 报告顺序：未发布答复方误填 placeholder → 参数错误而非发布错误 → message_bot 提交超过 2500 字答复 → 返回持久回执 → 最终内部正文不重复外发。
- 保存故障、保存中查询、长正文与思考隔离、重复/冲突提交、未知 ID、无权限读取、投递未确认、超时、授权撤销与重启恢复。
- 两个原生 DSH 实例 + Hub + mock：短时等待结束后，迟到结果通知唤回原远程会话，显式发布成功。
- 完整单元回归、宿主 52 步冒烟、构建一致性与 lint。

磁盘与宿主同时不可用时不能保证即时通知；保留原生历史和已保存记录，恢复后核对，不将未确认状态显示为成功。本轮不改变 Hub 协议、公开权限或正文默认不转发的规则。
