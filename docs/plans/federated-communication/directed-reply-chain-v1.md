# 定向回复链：实现与边界

2026-11-11，首次实现基于 V0.3.2；V0.3.3 将持久化收尾提醒上限调整为 3 次。
取代 [回复链广播草案](reply-chain-broadcast-v1.md) 的全参与者唤醒规则。

## 交互与派发

主输入框发新消息；点击回复继续既有链，链内不创建嵌套话题。
回复链负责展示上下文，**不是 Bot 广播订阅名单**。

| 人类发送方式 | 本条 Bot 处理对象 |
| --- | --- |
| @ 一个或多个 Bot | 这些当前可接收的 Bot |
| @all | 当前群内可接收的 Bot，不包含退休/只读身份 |
| 回复 Bot、没有任何 @ | 被回复消息的 Bot 作者 |
| 回复人类、没有 @ | 无 |
| 回复 A，同时 @B | A 与 B（回复隐含 @A，与显式 @ 合并去重） |
| 回复 A，同时只 @ 人类 | A |
| 主输入框无 @ | 群设置的默认接收列表；mentionsOnly 模式无 Bot |
| 人类 DM | 当前 DM 的 Bot |

主输入框和回复框上方都显示接收 Bot 的头像、名字、选中原因
（@、回复对象、默认接收、私聊）。没有目标时明确显示“不会唤醒 Bot”。
该栏表示模型处理请求，不改变其他成员读取群历史的权限，也不保证 Bot 回答。
手打 @、选择器、@all 和引用文字共用宿主的 mention 解析器；头像候选来自会话成员。

Hub 派发和客户端预览共用 `communication-hub/src/human-routing.js`；构建后规则
包含在插件 client.js 中，不要求部署时跨包导入源码。
新 Hub 声明 `directed-group-replies` 与 `reply-mention-union`（回复对象和 @ 的并集）。连接旧 Hub 时预览保留其原有回复回退语义，
不会声称旧 Hub 已支持新规则。预览依据最新本地成员快照；Hub 仍在提交时校验
实时成员与权限，因此成员变动、断线和发送失败不等于已唤醒。

被回复原文会独立放进所有被唤醒 Bot 的输入，包含真实作者、消息 ID 和正文；
不依赖最近 100 条历史窗口或已消费上下文游标。引用仅作为上下文，不作为新任务。
按每个接收 Bot 的会话、成员 epoch、入群边界读取；不可读时明确标记，不跨权限补取。

Bot 的普通最终回复不唤醒群内其他 Bot；需要追加工作时必须明确提供
activationTargets。显示性 @ 不替 Bot 自动申请工作。DM 仅恢复精确的原请求者，
普通确认不再次请求工作。因果根、去重、深度 8 / 总激活 32 默认保险继续有效。

## 不吞回复，也不自动泄漏正文

通过 DSH 公共 `agent/turn-stopping` hook 检查当前联邦输入的提交状态，不修改
DSH 内部循环。普通正文和 reasoning 默认都不外发。

- `reply_to_communication({text})` 显式提交新的公开回复。
- 遗漏提交时，每条输入最多提醒 3 次，逐次检查是否已提交；同一收尾事件不重复计数；提示包含工具名和已有普通正文的 `draftId`。
  `reply_to_communication({draftId})` 可明确选用原正文，无需重新生成。
- 草稿只引用同一绑定、投递、Session、回合及消息的 text 块，并验证摘要。
  reasoning、工具调用和不同来源的内容不能作为草稿提交。模型必须判断正文
  是否适合公开；内部汇报不可因“已有草稿”直接外发。
- `decline_communication_reply({})` 明确不回复，只生成控制回执，不生成聊天文本。
- 3 次提醒后仍不提交：`decision_missing` / `REPLY_DECISION_REQUIRED`；发送被拒：
  `send_failed` / `REPLY_SEND_FAILED`。均不会伪装成 no_reply 或关闭回复授权。
  用户可在通信活动中看到错误，routing-audit 可核对状态。
- 提醒次数和草稿引用持久化，重启不重置额度。后续提醒沿用最初保存的草稿引用，避免把纠错说明替换成待发送正文。已入 outbox 的提交沿用原意图重试，
  不能把 pending 当成“已对方处理”。遗漏后不进行无限模型重试。

## A 收集 B/C 的进展

`collect_communication_progress({text, activationTargets, waitSeconds})` 在当前群中
发送一个定向请求，然后在同一次工具执行内等待报告。默认/最大等待 30 秒。
被动 Bot 也可凭当前未结算的真实投递授权派发；不能凭空主动派活或复用已结算授权。

Hub `collection.status` 按请求的实际 AI 投递及 response grant 关联报告，只允许
请求者在同一 membershipEpoch 内查询。普通引用、伪造的“报告”文字不能满足等待。
多个回报不分别唤醒协调者；工具返回后 A 用原回复授权提交一次总结。

超时返回部分结果和 requestMessageId。用该 ID 再查/再等不会重新派发。
`pending`、`unavailable`、`no_reply` 与 `replied` 分开；报告文本有总长度上限，截断
明确标记。来源可关联不代表报告内容已获真值证明。

首版限制：没有后台长期等待器；超过等待期限的报告仍留在群记录中，但不会自动
开启新的协调者回合。后续需显式查询或由用户追问。不能保证任意闲聊无需 @ 就
会被所有 Bot 注意，也不能靠文字意图绕过权限/因果预算。

## 验证

- Hub：回复和 @ 并集去重、回复人类不回退、被动协调者授权、B/C 回报与不回复、禁止越权读取。
- 插件：草稿绑定与摘要、防止 reasoning 外发、有界提醒、显式拒答、遗漏/失败分离、头像规则。
- 双实例 DSH + Mock：DM 停止、被动接力、遗漏后 draftId 补交、协调收集、重启不重发。
- GUI：主框/回复框头像实时变化、深色引用、窄屏无横向溢出；交互不产生意外发送。

真实 LLM 的工具选择仍有不确定性；宿主提供有界纠正和可见错误，不声称所有模型
一定做出正确公开选择。未实现更大的 task/waiter/镜像输出提交重构。
