# 跨实例通信实施计划

> 入口：[总方案](../2026-11-03-federated-communication.md)。原方案创建时所有阶段均待开始。当前 P0–P4 已完成本机隔离 Mock 门禁，见 [P4 检查点](p4-acceptance.md) 和各阶段 evidence。不同 IP/WSS/真实模型仍未验证。用户追加需求在该检查点后继续实施；计划文字本身不表示通过。

## 1. 交付目标

在同一台开发机器上启动实例 A（人 A、Bot J）和实例 B（人 B、Bot K），连接一个共享通信服务。四个身份可以加入同一群，也能按授权建立双方私聊。文本消息正确入箱、正确显示，重试去重，断线和进程重启后恢复。

首版的开发完成点是可靠通信。消息内容中的“开始设计”“请确认”“进度如何”不进入任何内置业务流程。

## 4. P0：接口与隔离验证

### 工作

- 启动两个真正独立的 DSH Web，确认各自创建自己的 Chief 和数据，双方都可写。
- 用独立实例 ID、Human ID、Bot ID 建立最小名册，制造两个同名 Chief 测试消歧。
- 验证本机“通信会话 ID + 本地 Bot ID”到当前 DSH Session 的映射，换段后仍能定位正确会话。
- 验证公开 `createUserMessage`、`steer/followup`、`sessions.flush` 路径能保留并读取用于对账的消息/投递标识。
- 验证公开 API 能稳定定位通信会话里已持久的 Bot 输出，并在重启、换段后找回尚未导出到 outbox 的回复。
- 验证群投影只刷新 UI、不触发模型；真正指定的 Bot 入箱才触发正常响应。
- 验证 Bot 给人发消息可以作为正确作者显示和通知，而不把它伪装成人类输入再次喂给 Bot。
- 验证 `shell.overlay` 原位 pane、侧栏导航、输入焦点、切群和刷新，避免隐藏的原生输入框同时接收 Enter。
- 明确新增通信私聊与旧私聊的入口和映射；不得未经验证把各类消息混入一个“当前聊天”。

### 必须形成的结论

| 项目 | 通过条件 |
|---|---|
| 身份隔离 | A、B 的数据、登录和 Bot 身份独立 |
| 会话隔离 | 同一个 K 的群和不同私聊都有明确的输入目标 |
| 人类接收 | Bot 发给 B 的消息不会再次唤醒 K |
| 幂等对账 | 入箱和输出导出前后崩溃时，均可从公开 API 对账；无法判断时记录明确能力缺口并阻塞相应用例 |
| UI 投影 | 回放一条消息不会创建新的输入或 `@` 调度 |

如果公开 API 无法完成关键持久化对账或隔离，在这里记录精确缺口，携带最小复现向用户说明。不能改 DSH 内核、直接修改 DSH 日志、调用明确禁止外部插件使用的内部接口来隐藏缺口。

### 产出

- 最小可复现的双实例探针或测试。
- 一份短验证记录：版本、命令、结果、尚未支持的能力。
- 后续模块的接口草案；此阶段不要先铺完整 UI 或业务流程。

## 5. P1：通信服务与本地持久队列

### 工作

- 新增独立通信服务包，定义配置、数据库迁移、启动/停止和健康检查。
- 依[协议](protocol.md)实现实例配对、身份绑定、联系人、群与私聊。
- 对规范双方键实施事务性私聊 get-or-create；并发、反向创建和重试返回同一会话。
- 事务保存消息、顺序和投递记录，落盘后回执。
- 客户端 outbox/inbox、去重、重连、连续游标、丢失回执后的重发。
- 同一 ID 同内容返回原回执；同一 ID 不同内容返回冲突。
- 持久化成员版本、加入轮次与历史边界；撤权是旧投递的终态，重新加入不复活旧投递。
- 明确超长消息、未知协议和不支持附件的错误；正文不默默截断。
- 单机用 loopback；跨机器路径保留认证和 WSS 配置，不能通过“本机地址”跳过身份校验。

### 产出与检查

- 服务端和客户端通信模块的可运行入口。
- 配置模板只有地址、端口、数据路径及凭据引用；没有真实秘密。
- 用真实数据库和独立进程测试落盘、丢回执、重复、乱序、缺口和重启。
- 更新环境文档，将未来命令替换为已经实现、实测有效的命令。

## 6. P2：人、Bot 与 DSH 的正确收件

### 工作

- 增加统一身份解析器，分离 `Participant` 与只能在本机运行的 `LocalBot`。
- 远程名册存通信库；不向现有本机 Bot 表塞入伪 Session。
- 从已认证的人类 UI 入口确定发件人；从实际调用工具的本机 Bot 会话确定 Bot 发件人。
- 建立会话与本机 Bot Session 绑定，投递前再次验证成员、目标和当前绑定。
- 把网络同步显示、人的通知、Bot 入箱拆为不同函数和状态。
- 增加面向人和 Bot 的联系人发送工具，例如 `send_contact_message`；具体命名跟随仓库现有工具风格。
- 扩展 `list_bots`/联系人目录，使 Bot 能看到允许访问的人和远端 Bot 的精确寻址方式。
- `message_bot`、`post_to_group` 在联邦场景中使用确定的身份和会话；保留旧本地语义。
- Bot 输出只回到输入所绑定的通信会话，或经显式发送工具选择另一个目标；回复元数据可追踪。
- 实现 DSH 与本地通信库之间的双向恢复对账：入箱按 `deliveryId` 查证；Bot 输出保存源事件到 `messageId` 的映射、outbox 与导出游标。
- 历史同步只投影；离线未完成的投递按原收件资格继续消费，不能因消息已经显示就跳过入箱。

### 产出与检查

- 四种私聊方向的实际收件验证：人→人、人→Bot、Bot→人、Bot→Bot。
- 同一个 Bot 同时属于多个会话时，各输入和输出不交叉。
- 人类不在线或 Bot 不运行时仍能保存并显示相应消息状态。
- 此阶段不得新增任务记录、审核状态或自动开发逻辑。

## 7. P3：共享群与通信 UI

### 工作

- 混合成员选择器、邀请与加入、成员变更、稳定群身份。
- 群默认接收规则只在 Hub 计算；实现版本化的 `admin` / `mentionsOnly` 两种模式，同步各端只应用结果。
- `@人` 通知；`@Bot` 投递；多 Bot 点名分别处理；普通 Bot 回复不再次唤醒整个群。
- 同名成员的唯一别名、结构化提及和歧义提示。
- 各端相同消息 ID/顺序/正文，按本地查看者显示“你”“本地”“远程”。
- 通信主区、私聊入口、群成员面板、历史分页、未读和发送状态。
- 引用回复只引用可读的同会话消息；跨会话分享必须形成新的显式消息。
- 隐藏/退出/解散分别命名，不让一个本地操作意外改变所有成员的群。
- 按角色授权群操作；远端 Chief 不继承本地 Main Bot 管理权。
- 尚未支持的附件、共享记忆等入口禁用并说明，不能画出可点击但没有结果的按钮。

### 产出与检查

- 两个真实浏览器视图中的 A/J/B/K 共群演示。
- 接收者、作者、远程标识、提及和回复关系可检查。
- 长文本、重名、快速切换、刷新、重连、不同窗口宽度的实际 UI 检查。
- 修改 `src/client/` 后生成并提交对应 `client.js`。

## 8. P4：故障恢复与回归收尾

### 工作

- 按验收矩阵运行服务端和客户端崩溃注入、断线、重复、乱序及撤权。
- 特别覆盖：接收端 DSH 已落盘但插件尚未记录已入箱、插件已接收但 DSH 尚未接收，以及 Bot 回复已持久但 outbox 尚未提交的窗口。
- 检查输出映射、outbox 和导出游标的原子性；崩溃恢复既不能漏回复，也不能重新导出旧回复。
- 不确定状态必须可见、可诊断；必测用例不能以“用户手动看一下”代替协议对账。
- 完成纯本地私聊、建群、`message_bot`、原有群提及和现有 UI 的回归。
- 测试历史重放不会重新生成投递；原本未完成的收件和输出导出仍能完成，且重复恢复不重复消费。
- 增加有界缓冲、退避和背压；队列满或磁盘失败必须报明确错误，不能回成功。
- 关闭测试时只结束本轮启动的进程，保留恢复用数据；另行提供显式清理操作。

### 门禁

按仓库当时的 `AGENTS.md` 执行 `npm test`、构建一致性检查、lint；Host 改动跑真实 DSH smoke。Windows 若不能运行某个 shell 脚本，用已验证的 WSL 环境或实现并验证等价脚本，不能写“理论等价”就跳过。

真实模型可作为补充验证。缺少模型 API key 时问用户；Mock 已覆盖的通信项目可以继续，但真实模型项目必须标成待验证，不能将 Mock 结果冒充真实模型结果。

## 9. 建议代码组织

以下均为建议新增路径，基线中尚不存在：

| 路径 | 职责 |
|---|---|
| `communication-server/` | 协议接入、认证、会话事件库、投递、恢复 |
| `ds-bot/src/shared/communication/` | 纯数据契约、校验和稳定身份/提及；避免依赖 DSH 运行时 |
| `ds-bot/src/host/federation/` | 连接、队列、身份、会话映射、DSH 收件箱适配 |
| `ds-bot/src/client/communication/` | 通信主区、联系人、群/私聊列表与状态 |
| `ds-bot/dev/communication/` | 双实例启动/停止、协议故障代理、Mock 交互驱动 |
| `ds-bot/test/communication-*.test.js` | 适配、权限、路由与 UI 模型测试 |

若共享协议以包提供，需同时解决服务端依赖和 DS-Bot 发布包的可用性；不能依赖只存在于开发 checkout 上层的相对路径。`ds-bot/package.json` 的发布 `files`、安装用 bundle 和构建产物要包含所需模块。

保持现有 `install(rt)` 风格。增加生命周期清理：插件卸载/重启时停止重连、关闭连接和数据库，不能遗留重复消费者。
