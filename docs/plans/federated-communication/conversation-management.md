# Hidden, pinned and deleted remote conversations

Released in V0.4.2 together with remote-task local Bot exchange inspection. This user request replaces the earlier always-visible list decision.

Hide/show and pin/unpin apply to remote groups, Human DMs and the owner's read-only Bot DM records. Existing archived IDs are hidden IDs: no data or membership migration is needed. Hidden conversations remain received and saved, and remain hidden when new messages arrive. A separate collection restores them. Pins sort first within each existing list section; hidden pins stay hidden. Preferences belong to the current local Hub queue and persist across browser/host restarts. UI header actions and row context menus offer the same operations.

Deleting requires a separate modal confirmation with the conversation title and an explicit warning that local chat history cannot be restored. It does not leave/end a group, retire a Bot, revoke a contact, affect the Hub/other participants, or cancel queued messages/tasks. The captured local synchronized watermark bounds the deletion: messages arriving during confirmation or after a lost response are never accidentally deleted. Retrying the same cutoff is idempotent.

Deletion is a durable local owner-view history boundary. All owner history pages, references, reply chains, searches, latest-message previews and unread counts honor it. Existing synchronized protocol data, execution evidence, Bot working context, receipts and pending operations remain private and intact so deleting a UI conversation cannot replay work or corrupt synchronization. This is conversation deletion, not a secure disk erasure facility. There is no UI restore for deleted history. Later messages can return the row with only new history. Hiding has no such history boundary and is fully reversible.

Each mutation requires the exact current Hub preference scope and authorized Human or owned Bot-DM membership epoch. Read-only profiles cannot mutate preferences. A new history boundary also invalidates in-memory history/quote/thread contexts, including another open window. No Hub wire-protocol or capability bump is needed. The legacy archive CLI endpoint remains compatible; new endpoints describe hide/pin/delete directly.
