# V0.3.8：远程回合复用 Bot 本地权限

本批次包含小屏群成员设置和自动保存（00fd476），以及远程回合的本地权限统一。版本号等待本批次发布指令后统一升级。

## 身份与工具

远程会话绑定中的 `localBotRef` 参与 `selfOf`，因此团队管理、能力管理、浏览器和记忆工具复用同一 Bot 的本地权限判断。`isBotSession` 继续只表示本地回合，避免本地回合收尾机制接管远程正文、重新造成串台。

本地团队工具通过单独的授权包装注册；每次执行校验绑定、Hub 成员资格和工具是否仍然存在。原生与 MCP 工具从所属 Bot 当前可见的公共工具注册表动态继承，工具撤下后旧包装立即失效。本地本来禁用的 DSH 目标、子 Agent、工作流和阻塞提问工具继续禁用。

本地 Main Bot 身份、私有 Bot、记忆作用域、文件沙箱、审批和直接本机用户授权检查均由原有实现处理；远程显示名和群管理角色不授予本机权限。用户明确关闭本地记忆时继续尊重该设置。联系人与发布管理只接受当前原始消息作者为本机用户的精确 Hub 身份，且修改仍需本机原生审批；他人引用用户、远端 Bot 或相同显示名不能代替此授权。

## 读取本地消息

`read_own_chat` 增加 `message_id`，与 query、around、part 互斥。只扫描当前 Bot 自己的本地会话分段，通过 DSH 公共会话分页接口寻找精确消息 ID，返回完整正文、会话、分段和 seq。思考块不成为正文，不搜索其他 Bot 的会话；找不到时返回 `LOCAL_MESSAGE_NOT_FOUND`。读取结果标记 internal，不自动发布。

原生会话检索和事件读取工具在本地已启用时同样可用，继续使用原生工作目录授权及私有 Bot 保护。

## 本地与远端投递

`message_bot` 和 `stop_bot` 保留真实远程来源，本地请求不会与同一 Bot 的普通本地请求合并。本地回信保留来源并留在本地对话；需要在当前远程回合取得结果时继续使用 `consult_local_bot`。普通正文、思考和内部汇报均不自动转发到 Hub。

`ask_user`、`show_view` 和安全凭据卡片显示在所属 Bot 的本地用户对话，返回结果明确说明位置。定时工具管理所属 Bot 本地会话的任务，防止未来的定时输入被当作伪造的 Hub 投递。原生工具仍接收真实远程执行身份；仅定时服务使用经过绑定确认的本地任务目标。

## 验证

- 精确消息读取跨分段、完整正文、排除思考、不越权扫描其他 Bot。
- 普通 Bot 拒绝 Main Bot 专属操作，真实 Main Bot 保留本地权限。
- 原生/MCP 目录继承、工具撤回、成员撤销、执行身份、审批与定时目标。
- 本地协作保留远程来源，回复不进入远程会话，用户卡片目标正确。
- 双 DSH + Hub + mock：真实远程模型回合读取本地消息 ID，确认本地工具目录、共享记忆/Skills/AGENTS 和未发布本地同事的双向咨询。
